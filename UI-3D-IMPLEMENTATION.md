# UI and optional 3D implementation — 23 October 2026

## Inspection

The repository uses separate npm lockfiles for three applications. Mobile is Expo SDK 57, React 19.2, React Native 0.86 and TypeScript 6; navigation is existing state-based routing in App.tsx, and styling uses native StyleSheet/LinearGradient. Admin is React 19, TypeScript 5.7 and Vite 6 with existing CSS and Lucide icons. The API uses Express, Socket.IO, TypeScript and Zod, with scrypt passwords and hashed bearer sessions. Persistence is an atomic local JSON state file selected by DATA_FILE, rather than an external database. LiveKit audio requires server credentials. Existing rooms, gifts, games, wallet, rankings, profiles and moderation APIs were retained.

Git status was checked before editing. Existing mobile version/build metadata, EAS configuration and untracked output were preserved. No .env file, production data, API business logic, Git history or deployment settings were changed. Tests used local demo accounts and the existing isolated demo API state.

## Files and behavior

- `apps/mobile/GameLounge.tsx`: reusable game lobby header with actual room title and member count, restrained violet/mint accents and responsive text.
- `GameLobbyArtwork.tsx`, `GameLobbyPreview.tsx`: lightweight shared artwork and native fallback. Android does not import the web scene.
- `GameLobbyPreview.web.tsx`: explicit opt-in lazy import, Suspense artwork, WebGL2 detection, reduced-motion subscription, error boundary and close/unmount behavior.
- `GameLobbyScene.tsx`: procedural rounded dice, pips and an orbit ring; Three.js + Fiber Canvas + Drei Center. Pointer rotation and keyboard-accessible rotate buttons, capped DPR, low-power renderer and demand rendering. WebGL context loss falls back to artwork. No downloaded models, textures or external asset licenses are required.
- `apps/mobile/App.tsx`: connects the lounge and dark game cards to the existing game creation/join handlers; matching dark game header. Existing games and backend calls remain intact.
- `apps/admin/vite.config.ts`, `tsconfig.json`, `components.json`: Tailwind Vite integration, source alias and official shadcn configuration.
- `apps/admin/src/components/ui/{button,card,dialog,avatar,tabs,input,tooltip,skeleton,dropdown-menu}.tsx`, `src/lib/utils.ts`: CLI-generated reusable primitives.
- `ConsoleUI.tsx`: reusable loading skeleton, accessible moderation confirmation dialog, avatar/account menu and navigation tooltips.
- `main.tsx`: integrates primitives with existing auth/API handlers, report status tabs and mobile sign-out. Failed access updates keep the dialog open.
- `gaming.css`, `ui.css`, `shadcn-variants.css`, `style.css`: dark console theme, responsive layout, visible focus and reduced-motion support. Removed network font loading; uses system fallback fonts. The small MIT shadcn Tailwind variants are included locally so the CLI is not a retained application dependency.
- Both frontend package manifests/lockfiles changed. Admin's tracked tsconfig.tsbuildinfo was regenerated by its build. Prior mobile app.json/eas.json metadata changes were left intact.

Tailwind/shadcn apply to the DOM-based admin. Native screens retain their compatible existing primitives. Android deliberately uses 2D artwork to avoid adding a GL runtime or increasing native GPU/battery requirements; interactive 3D is currently web-only.

## Dependencies and commands

Mobile added `three@0.180.0`, `@react-three/fiber@9.8.2`, `@react-three/drei@10.7.9`, development `@types/three`, and Expo-compatible `@expo/metro-runtime@57.0.17` for production async chunk loading. Admin added Tailwind 4.3.3 / @tailwindcss/vite, radix-ui, class-variance-authority, cn and tw-animate-css; existing Lucide was reused.

Main commands executed:

```text
npm --prefix apps/admin install --save-dev tailwindcss@^4 @tailwindcss/vite@^4
npx shadcn@latest init --template vite --base radix --preset nova --yes --no-monorepo
npx shadcn@latest add card dialog avatar input tooltip skeleton dropdown-menu tabs --yes
npm --prefix apps/mobile install three@^0.180 @react-three/fiber@^9 @react-three/drei@^10
npm --prefix apps/mobile install --save-dev @types/three@^0.180
npx expo install @expo/metro-runtime
npm run check
npm test
npm --prefix apps/api run build
npm --prefix apps/admin run build
npm --prefix apps/mobile run build:web -- --output-dir ../../artifacts/ui3d/web-final
npx expo export --platform android --output-dir ../../artifacts/ui3d/android --source-maps --no-bytecode
npm --prefix apps/admin audit
npm --prefix apps/mobile audit --json
```

The shadcn and Expo commands ran in their respective frontend directories. The CLI's initial unsupported flags were corrected after reading its help. CLI-added font and CLI runtime packages were subsequently removed as unnecessary. The default mobile web export encountered a locked existing dist folder, so a separate ignored artifacts output was used without removing the prior output. Android's no-bytecode export was solely for inspecting its source map; it does not change the normal APK build settings.
