# Party API v1

Base `http://localhost:4000/api`. JSON responses are `{data: ...}`; errors `{error: {code,message}}`. Bearer token required except health, register/login/demo, catalogs. IDs strings. Dates ISO strings. Seed data is explicitly demo content. No real billing or RTC until configured.

Auth: POST `/auth/register` {name,email,password}; POST `/auth/login` {email,password}; POST `/auth/demo` {} (development only). Returns `{token,user}`. POST `/auth/logout`. GET/PATCH `/me` {name,bio,avatar,country}; GET `/users/:id`; POST/DELETE `/users/:id/follow`; POST/DELETE `/users/:id/block`; POST `/reports` {targetType,targetId,reason}. User public: {id,name,avatar,bio,country,followers,following,vip,demo}. GET `/me` additionally coins,diamonds,role.

Rooms: GET `/rooms?category=&q=` returns array {id,title,description,category,cover,ownerId,members,seats,locked,demo}; members are user IDs; seats array {index,userId,muted,locked}, eight positions. POST `/rooms` {title,description?,category?,cover?}; GET `/rooms/:id`; POST `/rooms/:id/join` {password?}; POST `/rooms/:id/leave`; PATCH `/rooms/:id` owner {title?,description?,locked?,password?}; POST `/rooms/:id/seats/:index` {action:'take'|'leave'|'mute'|'unmute'|'lock'|'unlock'} (mute/lock owner only, own seat leave); POST `/rooms/:id/kick` {userId}; GET/POST `/rooms/:id/messages` {text} membership required; POST `/rooms/:id/rtc-token` returns {token,url} only with LiveKit configured, otherwise 503 RTC_UNAVAILABLE. Rooms listing live membership begins empty; no fabricated live counts.

DMs: GET `/conversations` returns [{user:publicUser,lastMessage}]; GET/POST `/users/:id/messages` {text}; messages {id,fromId,toId?,roomId?,text,createdAt}. GET `/wallet` -> {coins,diamonds,ledger}; POST `/wallet/demo-credit` {amount:100} development only max1000/day; POST `/gifts/send` {recipientId,giftId,quantity:1,roomId?,idempotencyKey} -> {transaction,balance}. Gift catalog GET `/gifts` [{id,name,emoji,cost}]. No payment API.

Feed GET `/posts`; POST `/posts` {text,image?}; POST/DELETE `/posts/:id/like`; GET/POST `/posts/:id/comments` {text}. Posts include author,likes (IDs),commentCount,createdAt. Events GET `/events`; POST/DELETE `/events/:id/rsvp`. Families GET `/families`; POST `/families` {name,description?}; POST/DELETE `/families/:id/join`. GET `/rankings?period=weekly` -> [{user,diamonds,rank}]. GET `/tasks` -> [{id,title,reward,claimed}]; POST `/tasks/:id/claim` (daily-login). GET `/store` and `/vip` catalog only; purchases explicitly unavailable. GET `/admin/reports` admin only.

Socket.IO same origin, auth `{token}`. Server automatically joins private `user:<id>`; client emits `room:subscribe` roomId and callback for membership validation. Server emits `room:updated` room object, `room:message` message, `dm:message` message, `wallet:updated` {coins,diamonds}, `gift:sent` transaction. HTTP join also subscribes existing sockets to room. Seats are enforced on server. RTC token only grants publish if seated/unmuted; membership revocation disconnects configured LiveKit participants; seats changes disconnect to force token refresh.

Admin demo: POST /auth/admin-demo (development only) returns {token,user}. Admin-only: GET /admin/stats {users,rooms,activeMembers,reports,gifts,coinsTransferred}; GET /admin/users array with role/disabled; PATCH /admin/users/:id {disabled}; GET /admin/rooms; GET /admin/transactions; PATCH /admin/reports/:id {status:'open'|'resolved'|'dismissed'}. No production admin account seeded.

Games: GET /games; POST /games {roomId} creates server-authoritative tic-tac-toe; POST /games/:id/join; POST /games/:id/move {index:0..8}. Room membership required; no wagers. GET /rooms/:id/pk returns latest battle with scores; owner POST /rooms/:id/pk {opponentId,durationSeconds:60..600} starts gift-score PK. Both players must be members. Scores derived exclusively from gift ledger within battle window. Socket events game:updated and pk:updated.

Storage is atomic JSON snapshots for single-process local development. Horizontal workers and production concurrency require transactional PostgreSQL/Redis, migrations, durable jobs and backup policy. Do not run multiple API instances against the same DATA_FILE. No production admin user is seeded. Production administration bootstrap, billing, upload storage/scanning, moderation operations and actual RTC credentials remain deployment work.

Account management: POST `/me/password` {currentPassword,newPassword(min 8)} changes password, revokes all other sessions and sockets of the user (current session stays). GET `/me/export` returns {exportedAt,profile,messages,posts,comments,ledger} for the signed-in user. DELETE `/me` {password} (password not required for demo users) anonymises the account, removes it from rooms, seats and follow lists, disables login and revokes all sessions; ledger rows are kept for financial history. Email recovery (forgot password) still needs an email/SMS provider.

Audit log: GET `/admin/audit` (admin only) returns the latest 200 admin actions newest first: {id,at,adminId,adminName,action,targetType,targetId,detail}. Recorded actions: user.disable, user.restore, report.resolved/dismissed/open. Stored in state.audit, capped at 1000 entries.

Mic queue: GET `/rooms/:id/queue` -> [publicUser]; POST `/rooms/:id/queue` {action:'join'|'leave'}; owner POST `/rooms/:id/queue/promote` {userId?} seats the first (or given) queued member in a free unlocked seat. Socket `room:queue`.
Decorations: GET `/decorations` -> {coins,equipped,items:[{id,name,emoji,slot:'frame'|'entrance'|'badge',price,owned,equipped}]}; POST `/decorations/:id/buy` (coins), POST `/decorations/:id/equip`, DELETE `/decorations/slot/:slot`. Public users now include `equipped`.
Games: POST `/games/connect-four` {roomId}; join with `/games/:id/join`; POST `/games/:id/drop` {column:0..6}. `/games/:id/move` is tic-tac-toe only. Board is 6x7 flat, marks 'R'/'Y'.
Lucky bags: GET `/rooms/:id/lucky-bags`; POST `/rooms/:id/lucky-bags` {total:10..10000,count:2..20} deducts coins; POST `/lucky-bags/:id/claim` (one claim per member, not the sender). Unclaimed coins refund to the sender after 24h. Socket `room:lucky-bag`.
Tasks: GET `/tasks` now returns daily-login, send-gift, post-today, chat-in-room with `ready` and `claimed`; claim fails until the task is really done.
Phone OTP: POST `/auth/otp/request` {phone} and POST `/auth/otp/verify` {phone,code,name?}. In demo mode the request returns `devCode`; outside demo it returns 503 SMS_UNAVAILABLE until an SMS provider is wired in.
Password recovery: POST `/auth/password/request` {email} always answers `{sent:true}`; in demo mode an existing account also gets `devCode`. Outside demo it returns 503 EMAIL_UNAVAILABLE until an email provider is wired in. Max one request per 30s per email; code valid 15 min, 5 attempts. POST `/auth/password/reset` {email,code,newPassword(min 8)} sets the password, revokes every session and returns `{token,user}`.
Preferences: GET/PATCH `/me/settings` {privacy:{dmFromStrangers,showVisits},notify:{follows,gifts,comments,rooms}} (partial PATCH). `dmFromStrangers:false` rejects DMs (403 DM_RESTRICTED) unless the recipient follows the sender or already messaged them. `showVisits:false` stops recording your profile visits. `notify.*:false` keeps the notification in the list but suppresses the live socket pop-up.
VIP: GET `/vip` {available:true,plans:[{id,name,days,price}],benefits}; POST `/vip/:id/subscribe` pays coins, extends `vipUntil` from the current expiry and logs `vip-purchase`. Public users expose `vip` (false once expired) and `vipUntil`.
Wallet: GET `/wallet/packages` preview-only coin packages (`available:false`, no payment provider). POST `/wallet/exchange` {diamonds} multiples of 10, 10 diamonds -> 8 coins, logs `exchange`.
